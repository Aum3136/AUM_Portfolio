// 01 · THE PROBLEM

Nutrition apps lie with confidence.

Most nutrition trackers ask you to manually log food. Nobody does that for more than three days. NutriScann takes a photo, sends it to Gemini Vision, and gets back a full macronutrient breakdown — no barcode scanning, no database lookup, no manual entry.

The hard part wasn't the AI. It was making the system production-safe: auth that can't be bypassed, data that's scoped to the user, images that don't bloat your database, and an API that doesn't collapse under a free-tier Railway instance.

// 03 · WHAT ACTUALLY WENT WRONG

Production hardening is unglamorous work.

SECURITY INCIDENT

Live .env exposure

During development, a .env file was accidentally tracked and pushed. All keys were rotated immediately — Firebase, MongoDB Atlas, Cloudinary, Gemini. node_modules was removed from git history. .gitignore was audited. Incident closed in under 2 hours.

DATABASE

Base64 images in MongoDB

Early versions stored scanned food images as base64 strings directly in MongoDB documents. Documents ballooned to 2-3MB each. Migrated entirely to Cloudinary with a secure upload pipeline — MongoDB now stores only the URL.

AUTH

Client-side auth is not auth

V1 trusted the frontend to enforce user scoping. Replaced with Firebase Admin SDK middleware on every protected route — token verification happens server-side, userId is extracted from the decoded token, never from the request body.

// 05 · RETROSPECTIVE

If I built this again.

  • →
    Set up Cloudinary on day one. Migrating away from base64 mid-project touches more files than you expect.
  • →
    Write auth middleware before writing a single route. Retrofitting it is painful and you will miss edge cases.
  • →
    .env goes in .gitignore before the first commit. Not the second. Not after npm install. First.
