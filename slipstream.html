Slipstream Gateway

Middleware sitting between applications and multiple LLM providers (Groq, Gemini, local Ollama) to drastically reduce latency and cost while guaranteeing high availability.

Co-authored project built with teammate Naitik Lavri. My ownership: Semantic cache core, intelligent model router, and fallback/circuit-breaker engine. Teammate owned: Observability dashboard and guardrails screening layer.

// 01 · THE PROBLEM

Direct LLM API calls overpay and break easily.

Teams connecting software directly to LLM providers face three structural flaws: they pay full rate for every single API request (even identical or near-duplicate prompts), have zero automatic failover when a provider is rate-limited (HTTP 429) or offline (HTTP 503), and send every prompt to the exact same heavy model regardless of request complexity.

Slipstream Gateway acts as intelligent, resilient middleware. By intercepting outgoing requests before hitting upstream APIs, it enforces zero-cost screening, vector similarity cache retrieval, tier-based model allocation, and per-provider circuit breaking without the application needing to know which provider served the response.

3 - 4 ms Cache Hit Latency (vs 890ms live API call)

// 02 · SYSTEM ARCHITECTURE

5-Stage Left-to-Right Request Pipeline.

Requests flow left-to-right through cheapest checks first. Bad requests get filtered at zero cost, cached answers return in single-digit milliseconds, and live requests route to the cheapest viable model.

STAGE 01
Guardrails
Regex-based PII screening & prompt-injection filtering. Blocks malicious or invalid payloads before touching any model (0 cost).

// 03 · WHAT I ACTUALLY BUILT

Core engineering & architectural decisions.

DATABASE ARCHITECTURE

Two-Store Cache Architecture

Separated vector indexing from payload storage: ChromaDB manages high-dimensional vector similarity indexing while Redis stores raw response completion payloads.

Vector databases are optimized for nearest-neighbor search rather than large blob key-value storage. By indexing vector embeddings in ChromaDB and storing response blobs in Redis, query lookup and retrieval remain ultra-fast at scale.

SYSTEM RESILIENCE

Zero-Dependency Graceful Degradation

Built dual fallback mechanisms for local execution resilience: if sentence-transformers model weights cannot download, the pipeline switches to an offline hashing-based embedder.

If a Redis server is unreachable, the system seamlessly falls back to an in-memory fakeredis instance. The entire 5-stage pipeline can run locally with zero external network or service dependencies.

FAULT TOLERANCE

Per-Provider Circuit Breaker Pattern

Implemented explicit finite state machine states (Closed, Open, Half-Open) evaluated individually per provider tier rather than globally across the gateway.

When a provider hits consecutive rate limits (3 failures), its circuit opens for a 30-second cooldown period. Because breaker state is scoped per-provider, a dead provider (e.g. Groq 429) never blocks traffic from routing to healthy alternatives (e.g. Gemini or local Ollama).

DEVELOPER EXPERIENCE

Deterministic Offline Mock Mode

Architected a full offline mock mode where the complete 5-stage pipeline runs end-to-end with zero API keys using deterministic fake completions.

This allows developers to build, test, and run CI integration suites without incurring upstream API charges or requiring internet connectivity.

// 06 · LESSONS & RETROSPECTIVE

What building LLM infrastructure taught me.

  • ➔
    "Infrastructure" doesn't mean "machine learning" at every layer: The router and guardrails run on regex and length heuristics, not trained models — and that's fine. The harder engineering call wasn't writing a classifier, it was deciding which layer actually needed one. A vector-similarity cache is a real ML problem worth solving with embeddings. Sorting a prompt into "simple vs complex" is not — a heuristic gets 90% of the value at 0% of the training cost.
  • ➔
    A cache is only as good as its false-positive rate: The dangerous failure mode isn't a cache miss — it's a cache serving the wrong answer with full confidence because the similarity threshold was too loose. Tuning 0.80 cosine similarity meant testing genuine paraphrases against genuinely different questions, not just checking that identical prompts hit.
  • ➔
    Free-tier providers force you to build resilience you'd otherwise skip: Building on Groq/Gemini/Ollama instead of OpenAI meant real rate limits and real outages during dev — which is exactly why the circuit breaker exists per-provider, not globally. One dead provider doesn't get to take down the other two.
  • ➔
    Mock mode wasn't a shortcut — it was a design requirement: Being able to run the entire 5-stage pipeline with zero API keys meant the architecture had to be provider-agnostic from day one, not bolted on later. That constraint caught bugs in the fallback chain before a single real API call was made.
